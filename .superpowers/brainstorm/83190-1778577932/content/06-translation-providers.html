Adding one (e.g. "+ Add provider → DeepSeek")

┌─ New provider ───────────────────────────────────────────────┐ │ Name [ DeepSeek ] │ │ Endpoint [ https://api.deepseek.com/v1 ] ← prefilled by the preset │ API key [ •••••••••••••••••••••• ] │ │ Model [ deepseek-chat ▾ ] ↻ ← ↻ pulls /v1/models from the endpoint │ │ │ [ Test connection ] ✓ translated "Hello" → "你好" · 0.7 s · deepseek-chat │ │ │ │ [ Cancel ] [ Save ] │ └──────────────────────────────────────────────────────────────┘

"Test" does a real translation round-trip — sends one short string to the configured endpoint+model+target-language and shows the actual output + latency. That catches bad URL, bad key, wrong model name, no credits, weird response shape — all the things a "GET /v1/models" ping misses. (The backend already has POST /api/translator/test; we make it do this real roundtrip and return the sample translation. And the masked-key bug from part 2 is fixed, so Test keeps working after Save.)
