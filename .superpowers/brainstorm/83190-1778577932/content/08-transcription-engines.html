How "appear / size / what-works" is wired

Machine-compat verdictBackend exposes a system report: OS, arch, GPU vendor (apple / nvidia / amd / none), CUDA & Apple-MPS availability — extending what /api/version already hints at (cudaAvailable). Each engine has a small "requirements" descriptor; the UI computes ✓ works / ⚠ works but no acceleration here / ✗ won't help on this hardware and the "best for your machine" line.
"Installed?" detectionThe backend tries to import each engine's package. Present → the engine is selectable. Absent → it shows as an add-on with its download size.
Model weights = "downloadable, with size"For an installed engine, its models (tiny→large-v3, turbo) are listed with sizes; un-downloaded ones say "Download (X GB)" and stream progress — exactly the mechanism Whisper models already use (/api/dependencies). Nothing big is fetched until you ask.
Per-engine "variations"Each engine surfaces its real tunables — faster-whisper: compute type (int8 / int8_float16 / float16 / float32), beam size, VAD filter; WhisperX: + alignment + diarization toggle. All driven by per-engine metadata so the UI doesn't hardcode them.

The constraint you should know

Auto-installing a new engine's Python package at runtime works fine when the backend is a normal Python install (dev / from source) — pip install faster-whisper into the venv, done. But the packaged .app is a frozen PyInstaller bundle: it has no pip and you can't extend its site-packages. So in the shipped app, the realistic options are: (a) bundle the engines we support (fine for the small ones — faster-whisper + its ctranslate2 wheel only add ~40–60 MB; not fine for WhisperX/insanely-fast — pyannote/torchaudio/transformers would balloon the app by 1 GB+), or (b) ship them as a separate downloadable plugin archive the app unpacks into a user folder and adds to sys.path (a real little plugin system — more machinery).

So my recommendation: the packaged app bundles openai-whisper + faster-whisper (always there, just download the weights you want); WhisperX / insanely-fast-whisper appear in the list with their compat verdict + size but are "add-on (planned)" — the plugin-download mechanism for the heavy ones is its own future piece. Meanwhile a from-source install auto-detects whatever you've pip installed.

Scope note

Actually implementing the faster-whisper provider (and the plugin mechanism for the heavy engines) is real backend work — I'll carve it into its own spec, separate from "Settings tab production-ready". This Settings design just makes the Transcription tab engine-driven: it renders whatever engines + models + tunables the backend reports, with verdicts and sizes — so faster-whisper "just appears" the day its backend lands, and nothing here is fake in the meantime.
