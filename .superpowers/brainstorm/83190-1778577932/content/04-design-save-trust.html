Design — part 2 of 3: how saving works + the trust fixes

Hybrid save: safe stuff persists instantly; the few dangerous fields are "armed" — Edit → validate → apply. Plus the list of correctness bugs we're killing. Click ✓ to move on, or comment.

Safe fields — autosave, no buttons

Toggles, dropdowns, segmented controls, the subtitle numbers/colors, languages, VAD… change one, it debounces ~400 ms, writes, and a quiet "Saved" pill blinks on the tab footer. If the write fails you get a red "Couldn't save — retry" inline; nothing is silently lost.

"Armed" fields — Backend URL · Output folder · Download folder · Whisper cache · JS runtime path · mpv path

Read-only by default with a value + lock. Hit "Edit", change it, hit "Apply" — that runs a real check before committing: Backend URL → pings GET /api/version; folders → must exist & be writable; runtime path → must be executable. Pass = applied. Fail = stays put, shows why, with "Apply anyway" if you insist.

Backend URL http://127.0.0.1:8000 🔒 [ Edit ] ← resting state ───────────────────────────────────────────── Backend URL [ http://127.0.0.1:8000‸ ] [ Cancel ] [ Apply ] ← editing ───────────────────────────────────────────── Backend URL [ http://192.168.1.5:9000 ] ✗ no backend answered there [ Apply anyway ] ───────────────────────────────────────────── Backend URL http://127.0.0.1:8001 🔒 [ Edit ] ✓ applied · talking to it now ↺ Reset to 127.0.0.1:8000

Per-field "revert to default"

Hover any setting that differs from its shipped default → a small ↺ appears that puts it back. The footer's "Reset this tab" reverts the whole tab; Advanced has a real "Reset everything" (new POST /api/config/reset on the backend — today's "Reset to defaults" button is a lie, it just re-fetches your current config).

The trust / correctness fixes

Fake STT enginesDrop faster-whisper ⭐, WhisperX, insanely-fast-whisper and the ⭐. The backend only has openai-whisper + the YT-captions path — that's all the UI offers. (When a real new engine ships, it appears because /api/version → installedSttEngines says so.)
"Reset to defaults" is a lieToday it calls fetchConfig() → re-loads your saved config, not defaults. Fix: POST /api/config/reset returns asdict(AppConfig()) & persists it; the button (in Advanced, danger zone, with confirm) actually resets.
"Test" breaks after saving a keyGET masks the key to ***; the input round-trips that; Test then sends *** → fails. Fix: don't put the mask in the input — show •••• (saved) + "Replace"; Test, when no new key is typed, tells the backend "use the saved one" (useSavedKey: true) instead of the literal mask.
Wrong-platform copyplaceholder="C:\Users\you\Downloads" on a Mac app → gone. Placeholders show the actual resolved default (~/Downloads, the real output dir) — backend exposes effective defaults so the hint is true and the ↺-to-default knows the value.
Backend URL out in the openMoves to Advanced, becomes an "armed" field with validation + one-click reset (above). Stops being a foot-gun you can't undo without editing JSON.
Whisper model picker is blindDoesn't know which models are downloaded; offers all 6 equally. Fix: shows ✓ downloaded · size vs not downloaded · Download (streams /api/dependencies/install with progress). Settings & the Init screen stop diverging.
Cookie browser "(may fail)" guessworkKeep the Firefox-is-best guidance but lean on the real Test result (it already reports cookieSource / cookiesAttached) instead of pre-judging every option in its label.
Defaults vs. per-job is fuzzyEvery "default" gets one consistent line: "Default for new jobs — change it per-job on the Generate screen." So nobody thinks Settings is the only place to set it.
