2 · Adding a provider

+ Add provider opens a small menu: presets — DeepSeek · Groq · OpenRouter · Together · Mistral · xAI · Fireworks · OpenAI — or Custom…

Picking a preset prefills Name + Endpoint (the right base URL). You add the API key and pick a Model (type it, or hit ↻ to fetch the endpoint's /v1/models list).

Test connection in the form runs the real round-trip (below). It's not required to save, but the row warns if you save an untested one.

Save → it becomes a row in the list. Duplicate on an existing row clones it (handy for "DeepSeek-chat" + "DeepSeek-reasoner" with the same key).

3 · What "Test connection" actually does

Backend POST /api/translator/test — enhanced from today's version. It takes either an ad-hoc spec (endpoint+key+model, for testing before Save) or an existing provider id (uses the saved key — no mask round-trip, so it keeps working after Save). It then performs a genuine one-line translation: sends roughly "Translate the following to {target language}. Reply with only the translation.\n\nHello, world." and reads the response.

On success✓ "Hello, world." → "你好，世界。" · 0.7 s · deepseek-chat — proves the endpoint, key, model, and target-language all work end to end.
On failure, shows the real cause"401 — bad or missing API key" · "404 — model 'deepseek-x' not found" · "Couldn't reach api.deepseek.com (DNS/connection)" · "Timed out after 15 s" · "Endpoint replied but not in OpenAI chat-completions shape" · "Out of credits / quota exceeded".
GeminiSame idea via the Gemini SDK — a tiny generate_content roundtrip; surfaces "API key invalid", "model not enabled for your key", etc.
Local AISame roundtrip against the local server; surfaces "connection refused — is LM Studio's server running?" / "no model loaded".

openai_base_url / _api_key / _modelif non-empty → a saved provider named "OpenAI" (you can rename); else nothing

New config shape: custom_translators: [{id, name, base_url, api_key, model}] + active_translator = "gemini" | "local_openai" | "custom:<id>". OpenAICompatTranslator already exists and powers "OpenAI-compat" today — we're just letting there be many of them, named & persisted.

5 · Edge / safety states

Active provider's last Test failed → a banner on the tab (and on the Generate screen's translation toggle): "Translation may fail — DeepSeek's last test failed (401). Replace the key or pick another provider."

Delete the active provider → you're prompted to pick a new active one (can't be left with none; Gemini is the fallback).

Translation turned off by default → the provider list is still editable (greyed-but-usable), so you can set it up before you need it.

These providers also feed the Generate screen's per-job translator picker — so a single job can use DeepSeek while your default stays Gemini. (That Generate-screen change is noted as out-of-scope-for-the-Settings-spec but on the list.)
