Settings — how should it be organized?

~30 settings across 6 logical groups (General · YouTube/cookies · Transcription · Translation · Subtitles · Advanced). Today it's one long vertical scroll with no nav. Pick the structure that feels right — click an option.

A

Single scroll + sticky section nav

Keep one scrolling page (Cmd-F still works), but add a sticky in-page nav that scroll-spies and jump-links. Smallest change from today; most familiar.

┌────────────┬───────────────────────────────────────────────┐ │ yt·subtitle│ Settings │ │ │ ┌── On this page ──┐ │ │ Generate │ │ General │ ▸ General │ │ Library │ │ YouTube │ Backend · Folders │ │ History │ │ Transcription │ ▸ YouTube & cookies │ │ Settings ◂ │ │ Translation │ ... │ │ About │ │ Subtitles │ ▸ Transcription │ │ │ │ Advanced │ ... (scrolls) │ │ │ └──────────────────┘ │ │ │ ───────────────────────────────────────────── │ │ │ unsaved changes [Discard] [Save] ◂──sticky│ └────────────┴───────────────────────────────────────────────┘

Pros

  • Least disruptive — same content, just navigable
  • Find-in-page works; deep-linkable
  • You see "everything" at once

Cons

  • Still a long page
  • "Advanced" can quietly hide important things
B

Sub-tab rail — one focused panel at a time recommended

Settings gets its own narrow rail (General · YouTube · Transcription · Translation · Subtitles · Advanced). Click → that panel only, no scrolling past irrelevant stuff. What VS Code / Slack / Discord / macOS System Settings all do. We can add a search box at the top of the panel.

┌────────────┬──────────┬────────────────────────────────────┐ │ yt·subtitle│ Settings │ 🔎 search settings… │ │ │ │ ───────────────────────────────── │ │ Generate │ General │ Transcription │ │ Library │ YouTube │ │ │ History │ Transcr.◂│ Default engine [openai-whisper ▾]│ │ Settings ◂ │ Translate│ Default model [turbo ▾] ⬇ get │ │ About │ Subtitles│ Default device [auto ▾] │ │ │ Advanced │ Source language [English ▾] │ │ │ │ ▸ YT captions first [ on ] │ │ │ │ ▸ VAD by default [ on ] │ │ │ │ ───────────────────────────────── │ │ │ │ saved ✓ [Save] │ └────────────┴──────────┴────────────────────────────────────┘

Pros

  • Every screen is short & focused
  • Scales — adding settings doesn't lengthen anything
  • The "production desktop app" pattern
  • Search box becomes natural to add

Cons

  • A sub-rail inside the app's main sidebar — two levels of nav
  • Slightly more work to build
C

Search-first / settings palette

A big search box at the top is the primary way in — type "cookie", "gemini", "outline color" and it filters to matching settings; the grouped sections sit below as the browse fallback. Power-user oriented.

┌────────────┬───────────────────────────────────────────────┐ │ yt·subtitle│ Settings │ │ │ ┌─────────────────────────────────────────┐ │ │ Generate │ │ 🔎 outline │ │ │ Library │ └─────────────────────────────────────────┘ │ │ History │ 3 results │ │ Settings ◂ │ Subtitles › Outline color [#000000] │ │ About │ Subtitles › Outline width [3] │ │ │ Subtitles › Background [(none)] │ │ │ ───────────────────────────────────────────── │ │ │ (clear search → grouped sections below) │ └────────────┴───────────────────────────────────────────────┘

Pros

  • Fastest to a known setting
  • Great once there are lots of settings

Cons

  • Search-first feels odd for an app with only ~30 settings
  • Still needs a good browse structure underneath — so it's "B + search" really
